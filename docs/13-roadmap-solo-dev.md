# Solo-developer roadmap and the definition of production-grade

**Honest framing.** Five months is ~22 weeks. All three proposals carry the same scope; A's 20 weeks under-budgets docint and delivery by ~2×, B's 28 leaves the retailer product outside the window. This plan is **24 weeks P50, 28 weeks P80**, using B's slice durations and acceptance criteria, A's dependency order and cut line, and C's placement of WhatsApp intake and the PWA before cut-over. Tell Tarsun "parallel run around week 22, cut-over between weeks 24 and 26". Assumes ~45 productive hours/week, no hires until the base exists.

**Definition of production-grade (the pilot does not ship without this).**

| Area       | Bar                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tests      | `backend/libs/domain` ≥ 90% line coverage with golden cases from invoices A–G; integration on real Postgres: RLS isolation (cross-tenant fails; rep SELECT on costs returns 0 rows; retailer cannot update credit_limit), ledger invariants (balances = Σ ledger; Σ debit = Σ credit), idempotency and upload-log replay; sync conflict tests for every §7.3 rule; role-leak dump; docint eval on every model/prompt change; contract tests for `/sync/upload` v1 and Tally XML; Maestro journeys before each store release |
| Monitoring | OTel; structured logs with tenant/actor/request ids; Sentry on four surfaces with release tags; the §11 alarms; synthetic checks from India and outside; on-call = the founder's phone via Grafana OnCall; weekly cost report per tenant                                                                                                                                                                                                                                                                              |
| Backups    | PITR + nightly Object-Locked `pg_dump` + `backup.verify` + monthly restore drill with ledger checksum, first drill before first data; S3 versioning; RPO 5 min / RTO 2 h                                                                                                                                                                                                                                                                                                                                              |
| Security   | TLS everywhere; RLS forced; no `BYPASSRLS` reachable by the app; secrets in Secrets Manager with per-tenant KMS envelopes; OTP rate limits and spend alarm; device session revocation; short-TTL signed URLs; audit log on approvals, price, credit, cost views; dependency audit; DPDP notices, retention jobs, 72-hour breach runbook; no PII in URLs or logs; penetration checklist before the second paying tenant                                                                                                |
| Releases   | Blue/green with rollback; expand/contract migrations; EAS Update with runtime-version gating; one native release per quarter; changelog and feature-request channel visible to customers                                                                                                                                                                                                                                                                                                                              |
| Docs       | ADRs, runbooks, glossary, onboarding checklist — enough for hire #1 to deploy without the founder                                                                                                                                                                                                                                                                                                                                                                                                                     |
