## B. Adopted — rules now written into the domain (no schema change)

- **Pricing arithmetic** [14, 17, 18]: `priceOrder()` in `backend/libs/domain`: unit price = override else tier; gross = price × billed qty (free qty excluded); line rules in `priority asc, id asc`, `free_qty` first, then pct/flat rules **compounding** on the running net, rounded half-up to paise per step, first `final` rule stops the chain; order-level rules on Σ scoped nets, allocated to lines by largest remainder (`allocate()`); approved bargain last; cash discount per `cash_discount_mode`; tax per line at the dated HSN rate; total rounded to the rupee (s.170) with the residue to Round Off; warn when net rate > MRP. Applicability: any listed dimension restricts, dimensions intersect, empty = all. Slabs: highest achieved slab only. Free goods on `mix` triggers: fixed `freeVariantId` else the cheapest qualifying line. GST on free goods: composite supply, free line printed at ₹0 with qty, HSN summary counts actual qty.
- **Case size precedence** [8]: buy-side pack = `supplier_pack_configs` (procurement/GRN only); sell-side pack = `tenant_products.case_size_override` else `product_variants.default_case_size`, exposed as `sellCaseSize()` and used by orders, picklists, invoices and scheme triggers. Review screen: unknown case size → the reviewer types it (the second permitted typed number) and a `supplier_pack_configs` row is upserted [10].
- **Numbering** [20, 21]: ≤ 16 chars `[A-Za-z0-9/-]`, consecutive per series per FY, allocated only at issue (pack), never at draft; invoices cancelled before dispatch keep the number with `state = cancelled` (GSTR-1 Table 13) and reverse stock/AR by compensating rows; after dispatch only a credit note. `businessDate()` / FY pinned to `Asia/Kolkata`; device clock skew > 10 min on upload → `sync_errors` warning, never 4xx. The verdicts confirm cancellation is lawful, so "never regenerated" means "never _edited_".
- **Brand-DMS invoices enter before loading, not at day-end** [1]: committing a `brand_dms_invoice` document creates `sales_orders(source = brand_dms_import, state = packed)`, an `invoices` row in the external series carrying the DMS number, and a candidate trip stop; day-end is a reconciliation count.
- **Retailer identity** [26–28, 31]: identity = person (phone), `retailers` = shop, N identities per shop and N shops per identity via `retailer_links.role`. Rep onboarding always creates the tenant row and never queries the global table (no existence leak); the global identity is created/linked on the retailer's first OTP login. Numbers inactive > 6 months need distributor re-confirmation before ledger data shows. Directory shows shop name, area/pincode, category, opt-in date only.
- **GPS / DPDP** [32–35]: basis is employment; `location_consents` stores acknowledgement of the notice; denied OS permission never blocks a trip (owner sees "location unavailable"); raw `trip_points` expire after 90 days, stop coordinates and POD stay with the invoice; retailer gets ETA only. Android: trip tracking uses a **foreground service of type location while the trip is active, not `ACCESS_BACKGROUND_LOCATION`** (verdict: the background permission's Play review is unnecessary for a trip-scoped design).
- **Security** [54–57]: `schemes` reach rep devices through a view without `funding_source`, `claimable`, `claim_window_days`; claims never sync to reps; SQLCipher on from day one (op-sqlite, key in Keychain/Keystore, wipe on revocation); platform `support` access is a time-boxed, owner-approved, audited grant; owner app-lock for cost/profit screens; PowerSync JWT TTL 5 min.
- **Infra** (verdicts): `set_config(..., true)` pins RDS Proxy sessions → no RDS Proxy; direct connections for API, notifier and the replication slot (D11 stands, rationale corrected). RDS line is ~$34 not $31 (gp3 storage); T4g Unlimited surplus credits go on the alarm list. PowerSync bills **peak concurrent** clients, so retailer installs would not break the free tier; retailers stay online-first for simplicity, not cost. WhatsApp utility templates ₹0.115 + 18 % GST; in-window free utility is time-limited, budget ₹0.136 per message. NestJS 12 + oRPC + Drizzle + pg-boss verified running in this repo; ADR 0011's fallback to Nest 11 is closed.
- **Hindi UX** [36–40]: locales `en`, `hi`, `hi-Latn` (Hinglish candidate for staff), Latin numerals, `dd/MM/yyyy`; PDFs by headless Chromium in the worker with Noto Sans Devanagari, A4 + 80 mm; search normalises Devanagari/Latin aliases.
- **Tests** [49–52]: pricing golden fixtures `docs/fixtures/pricing/*.json` typed from invoices E and F; docint acceptance: line recall ≥ 98 %, amount fields ≥ 99.5 %, ≤ 1.5 edits per 10-line invoice; load model 300 orders/day, 80 devices, 3,000 GPS points/hour; a test enumerating every `tenant_id` table asserting FORCE RLS + a policy.
- **Backups / migration** [41–48]: restore drill runbook incl. PowerSync slot re-create; Object Lock 35 days in a separate account/KMS key; per-tenant undo by `import_job_id`; outstanding migrated from TradeEzee + FieldAssist + the physical file with a per-retailer variance screen and a WhatsApp "Reply 1 to confirm" opening balance; opening lots `batch_no = 'OPENING'`; cut-over runbook (freeze T, series decision, 30-day read-only TradeEzee).

**Consequences to honour when building:**

- Receivables: no salesperson receipts (see 4). Delivery collections and retailer online payments are the two field paths.
- Billing: B2B tax invoice first (see 3); one tenant-wide series, configurable (see 1 and 5); cash discount realised at receipt (see 2).
- Tenant settings need `display_name`, `logo_asset_id`, `invoice_footer` and the numbering configuration exposed in the owner app.
- The design phase must produce a product brand AND prove the white-label case in the mockups (show a distributor's own name in the app chrome).
- Integrations: build the generic mapped importer FIRST (upload → preview → map columns → save profile → dry run → commit), with per-source saved profiles layered on top. Never hard-code one vendor's column names. Opening balances must import as journal entries against the OPENING account so the ledger stays balanced, and a migration run must be reversible before it is confirmed.
