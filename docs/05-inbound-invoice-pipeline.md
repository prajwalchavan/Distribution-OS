# Inbound invoice pipeline (photo/PDF → GRN)

Principle (R05 §7, R06 §6): **QR first, structured pull where a session exists, vision extraction always, human commit always.** "Zero manual entry" means zero manual **typing**; the one deliberate number is the blind gate count **[CHANGE]** (R06 §9.3). Code lives in `backend/docint/{schema,validators,matcher,engines,eval}` as a library with pure validators, a matcher and a CLI eval harness, called by the worker (B's layout, resolved).

| Step                                | Where                                           | What happens                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------------------------- | ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0 Capture                           | Team app, offline OK                            | Blind gate count first. Document scanner, multi-page, JPEG q ≥ 90, originals kept; PDF share-in; each page passes QR detection. Originals to S3 `tenant/{id}/docs/{doc_id}/page-{n}.jpg` via the attachment queue; never downscaled                                                                                                                                                                             |
| 1 QR verify                         | Device, re-verified on server                   | Parse the RS256 JWT, verify against cached IRP keys by `kid`, extract the 10 fields (SellerGstin, BuyerGstin, DocNo, DocTyp, DocDt, TotInvVal, ItemCnt, MainHsnCode, Irn, IrnDt). Header card "Verified e-invoice from Reliance Retail ₹54,597" appears instantly                                                                                                                                               |
| 2 Pre-classify                      | Worker                                          | Dedupe on IRN (or supplier GSTIN + no + date); resolve supplier by GSTIN with `einvoice_expected`; `BuyerGstin == tenant.gstin`; select prompt profile (`tally`, `sap-reliance`, `guiltfree-dms`, `marg-gst-local`, `brand-dms-secondary`)                                                                                                                                                                      |
| 3 Structured pull (async, optional) | Worker                                          | EWB `GetEwayBill` if the number is printed and EWB credentials exist; `Get e-Invoice by IRN` if a GST taxpayer session is live; strip `Ph`/`Em`. **R05 §2.1 caveat carried:** the JSON gives HSN, qty, UQC, rate, discount, taxable and GST split but **not MRP, case size, scheme/GST-benefit % or batch unless the seller fills `BchDtls`** — vision remains mandatory; the pull is a cross-check skeleton    |
| 4 Vision extraction                 | Worker → `ExtractionEngine`                     | One request per invoice, all pages as labelled images at 2,576 px long edge; Claude Sonnet 5 `json_schema` output (R06 §8: raw-as-printed + normalised + per-line evidence + `handwritten_annotations[]`), cached system prompt + schema, adaptive thinking medium, streaming; **>20 images triggers the 2,000 px cap, so long invoices split with a continuity check**; Gemini 3.x Flash second opinion logged |
| 5 Validators (pure)                 | Worker                                          | GSTIN mod-36 with confusion-set retry; intra/inter-state split vs state codes; HSN length and dated rate; line arithmetic; Section 170 rounding ±₹1; Σ lines = subtotal; page completeness; QR: line count = `ItemCnt`, total = `TotInvVal` ±₹2; IRN hash `SHA256(SellerGstin + FY + DocTyp + upper(DocNo))` when QR failed; per-line agreement with step 3                                                     |
| 6 Pack-size normalisation           | Worker                                          | Parse "x 90", "_120", "(16+5.5)", "CS1", "2 Case", `Boxes`; `case_size = pcs / cases`; triangulate with name token and `supplier_pack_configs`                                                                                                                                                                                                                                                                  |
| 7 Escalation                        | Worker                                          | ≥ 2 red arithmetic checks or page mismatch → Opus 5 (or Gemini), keep the version passing more checks, log both                                                                                                                                                                                                                                                                                                 |
| 8 SKU cascade                       | Worker                                          | `supplier_aliases` exact → `product_external_codes` (494607257, Guiltfree code, DMS Item ERP Id) → HSN prefix + brand + MRP + pack filter → `pg_trgm` top-20 → logistic fusion → ≥ 0.90 green, 0.60–0.90 amber (top-3 chips), < 0.60 red. pgvector only if the eval shows the cascade stalls                                                                                                                    |
| 9 Three-way match                   | Worker + UI                                     | PO cases vs invoiced pcs ÷ case size; LR packages vs invoice cases; gate count vs LR. Gate < LR → transporter claim with mandatory damage photos before close                                                                                                                                                                                                                                                   |
| 10 Review                           | Team app                                        | `review_sessions` single-writer lock; header card (computed vs printed, IRN badge); line cards with row crop, chip, qty pcs/cases, MRP, rate; keypad edits; candidate sheet; swipe short/damaged; batch/expiry step (lot = batch + MRP + expiry); annotation panel (never alters printed values); LR panel; commit disabled while any red remains; resumable. Target: clean 10-line invoice < 60 s              |
| 11 Commit                           | API, one transaction, idempotent on document id | `supplier_invoices` + lines, `stock_lots`, `stock_ledger` `grn` rows, `stock_balances`, `tenant_product_costs`, `inbound_discrepancies`, AP journal, alias/code/pack-config upserts, `corrections_log`, outbox; 15-minute undo = compensating rows                                                                                                                                                              |
| 12 Reconciliation (later)           | Worker                                          | Monthly purchase e-invoice list → received on GST but never scanned; GSTR-2B/IMS view; never used for goods receipt                                                                                                                                                                                                                                                                                             |

**Brand-DMS invoices** (`brand_dms_invoice`, Too Yumm) run steps 0, 4, 5, 8 and a variant of 11: the retailer is matched by name/phone/beat/`Buyer ERP Id`, and commit creates a sales invoice `source = brand_dms_import` stamping SO/IN/ERP ids and posting stock out and AR in. The physical pending-bills file migrates as `retailer_ledger_migration` with the mandatory human checkpoint.

### 5.1 Failure modes (the review screen's acceptance checklist)

| Failure                                               | Detection → handling                                                                                                                       |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| QR unreadable                                         | Decode fails → continue on vision; IRN hash recompute if printed; amber "not verified"                                                     |
| QR signature fails (`kid` rotation)                   | Refresh IRP keys; else `qr_unverified`, never block                                                                                        |
| `BuyerGstin ≠ tenant`                                 | Red; commit only with owner approval (branch/consignee)                                                                                    |
| Duplicate IRN / (supplier, no, date)                  | Show existing GRN; block; "revised copy" only via debit/credit-note flow                                                                   |
| Large supplier without QR                             | `einvoice_expected` → amber                                                                                                                |
| Missing pages ("1 of 5", 3 captured)                  | Red; capture prompt; commit blocked                                                                                                        |
| Line count ≠ `ItemCnt`; totals off > ₹2               | Red; merged/split rows highlighted via row evidence; escalation run                                                                        |
| Unknown SKU                                           | Red → "create product" as `proposed`; curator merges via `merged_into`                                                                     |
| Case-size disagreement                                | Amber with all three values; reviewer picks; `supplier_pack_configs` upsert                                                                |
| Batch-tracked line without batch                      | Batch/expiry required before commit                                                                                                        |
| Multiple MRPs for one SKU                             | Separate lots per line                                                                                                                     |
| LR packages ≠ gate count; gate = LR but pcs < invoice | Transporter claim with photos; supplier shortage per brand policy                                                                          |
| LLM down, timeout, rate limit                         | pg-boss retry ×3; then `extraction_failed` — **manual typing allowed only here and measured** on the admin dashboard; capture never blocks |
| Schema grammar latency                                | Warm the schema in staging before deploy                                                                                                   |
| Structured pull fails                                 | Skip silently; reconciliation retries; monthly "re-authorise GST" nudge                                                                    |
| Blurry page                                           | Amber "retake page n"; may proceed                                                                                                         |
| Handwritten marks                                     | Shown separately, applied or dismissed; Claude's measured weak spot (R06 §5)                                                               |
| Hallucinated line                                     | Missing `evidence.row_text`, Σ mismatch, QR line count → red with row crop                                                                 |
| Supplier format drift                                 | Per-supplier edit rate rises → nightly alert; eval set and profile extended                                                                |
| Two managers on one document                          | Second sees read-only with the holder's name                                                                                               |

### 5.2 Eval before trust (resolved timing)

Collecting and labelling Tarsun's invoices needs no code, so it starts in **week 1**: 50–100 real inbound invoices across suppliers, both e-invoice classes, bad photos and pencil marks (R06 §11). Labelled by week 6, scored in week 10 before the pipeline touches real data, on field accuracy, line recall/precision and review edits per invoice for Sonnet 5, Opus 5, Haiku 4.5 (standard-res, to learn whether 1,568 px survives 8-pt Tally text) and Gemini 3.x Flash/Pro. **Sonnet 5 is the prior, not the decision:** R06 §3.1 shows Gemini 3 Pro/Flash above Claude on scanned invoices and Claude at 70% vs GPT-5 mini 88% on handwriting. The engine sits behind one interface. C's "Vertex AI Mumbai" for Claude is unverified; Vertex regional endpoints at a 10% premium (R06 §4) are the residency path if a brand asks.
