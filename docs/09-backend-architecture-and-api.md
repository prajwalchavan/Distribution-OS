# Backend architecture and API contracts

**Stack (pinned).** Node 24 LTS; NestJS 12 on Fastify; Drizzle 0.45.x with SQL migrations and RLS policies as code, raw `sql` for ledger statements; Zod 4 in `backend/libs/contracts`; oRPC with TanStack Query bindings and OpenAPI generation; pg-boss 12 for jobs and the outbox; Better Auth (`phoneNumber`, `organization`, `jwt`); CASL in `backend/libs/domain`; OpenTelemetry via `@nestjs/observe` to Grafana Cloud; Sentry. Runner-up if decorators grate: Hono + oRPC with the same `shared/` and database (R08 §1.2).

**Stack-freshness rule (resolved).** NestJS 12 shipped on 27 Aug 2026; Expo 57, Drizzle pre-1.0, Better Auth, oRPC and PowerSync JS v2 are all "latest". Week 1 includes a half-day spike: Better Auth, the oRPC Nest adapter, pg-boss, Drizzle 0.45, Sentry and `@nestjs/observe` on ESM Nest 12. If any fails, start on NestJS 11 with an upgrade ADR. Every version pinned; framework and SDK bumps only in the quarterly native release window. R08's "Node 22 EOL July 2026" is doubtful (maintenance runs to April 2027) but immaterial: Node 24 is Active LTS.

**Module layout.** Each module: `domain/` (pure TS, imports only `backend/libs/domain`), `application/`, `infrastructure/` (Drizzle repositories, adapters), `http/` (oRPC implementations), `events.ts`, `<module>.module.ts`. Cross-cutting in `common/`: `TenantContextGuard` (refuses requests without a resolved tenant), `TxManager` (`set_config` at transaction start), `IdempotencyInterceptor`, SSE hub, hi/en error mapping.

**API style.** oRPC procedures with Zod input/output in `backend/libs/contracts`, served by Nest, emitted as OpenAPI in CI for the Tally Connector, importers and future brand/ONDC adapters. No GraphQL (ledger writes want explicit commands), no tRPC (no OpenAPI for free). Every mutating procedure declares `idempotencyKey`; a different request hash under the same key returns 409. Non-oRPC endpoints: `POST /sync/upload` (`X-Sync-Protocol: 1`), `POST /gps/points`, `GET /health`, `/webhooks/whatsapp`, later `/webhooks/gsp` and `/connector/tally/*` (polling; no inbound ports on the customer LAN). Realtime: `@Sse()` for dashboard tiles, approvals, order status and `vehicle_positions`, ids only, fan-out via `LISTEN/NOTIFY` on a **dedicated direct connection**.

**Jobs (pg-boss, same Postgres).** `outbox.*` (enqueued inside the business transaction), `docint.extract|escalate|structured_pull`, `notify.whatsapp|sms|push` (per-tenant rate limit, cost logged), `reporting.rollup` (00:30 IST), `inventory.rederive_balances` (nightly, drift alarm), `receivables.ageing_snapshot`, `gps.summarise`, `dpdp.gps_retention`, `dpdp.erasure`, `integrations.tally_export`, `integrations.import_batch` (rate-limited, checkpoint rows), `backup.verify`; later `claims.window_reminder`, `gst.ewb_expected_deliveries`, `gst.session_refresh`. Move only notification fan-out to BullMQ on Valkey if pg-boss exceeds ~10% of primary CPU (R08 §5).

**Auth and RBAC.** Phone OTP via WhatsApp authentication template (₹0.115) with MSG91 SMS fallback after ~20 s; email/passkey for owners; long-lived staff sessions with device-bound revocation from the console; OTP rate limits per phone and IP; SMS budget alarm. Roles: `owner`, `manager`, `salesperson`, `delivery`, `accountant`, `retailer`; platform `curator`, `support`. Three layers: org role → transaction settings; CASL abilities identical in apps and API (`cannot('read','Product',['purchasePrice','margin'])`, `cannot('update','Retailer',['creditLimit','tier'])`); RLS as the last word. Per-tenant KMS envelope keys for GSP and WhatsApp credentials (B).

**Pooling (resolved).** No RDS Proxy at pilot: 1–2 Fargate tasks with an in-process pool suffice; `LISTEN/NOTIFY` and the replication slot need direct connections anyway; the proxy costs ~$22/month B did not table. Adopt transaction-mode pooling only above ~3 API tasks, after verifying it does not pin connections on `set_config(..., true)`.
