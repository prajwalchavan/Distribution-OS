# Offline sync design (Team app only)

> **Superseded 2026-09-05 (founder, docs/22 §8 / docs/26 §5):** offline sync is built in-house — the existing `/sync/upload` path plus a per-table delta pull keyed on `(tenant_id, updated_at)` into SQLite on the device. PowerSync is not used. The rules below (upload never 4xx, `sync_ops`, GPS outside the queue, LWW with backend veto) still apply; the transport paragraphs about PowerSync Cloud, logical replication and residency do not.

### 7.1 Engine and residency

PowerSync over Postgres logical replication (R07 §3): server-authoritative, per-user partial sync via Sync Streams keyed on JWT claims, FIFO upload queue, per-field LWW with backend veto, attachment queue, `@powersync/react-native` 2.2 with op-sqlite. ElectricSQL (no write path, cloud winding down), WatermelonDB (dormant), Replicache (maintenance) and Zero (rejects offline writes) are ruled out. RDS: `rds.logical_replication = 1`, a `powersync` publication limited to synced tables (never `FOR ALL TABLES`), replication role, TLS, security group restricted to PowerSync egress IPs, `max_slot_wal_keep_size` set with a slot-lag alarm (R07 §3.2 rule 8).

**Residency (resolved).** Week 1: verify whether PowerSync Cloud offers an India region. If yes, use it. If not, proceed on Cloud for the pilot with the fact recorded in the security note (DPDP does not mandate residency today, R08 §6.1) and keep the self-hosted Open Edition on ECS Mumbai as the exit, taken only when a paying tenant or brand partner demands residency — the Open Edition has no dashboard and no custom write checkpoints (R07 §3.2 rule 9) and is real ops load for one person. `frontend/libs/offline` is the only PowerSync-touching code. Cloud Free at pilot, Pro ($49) at ~10 tenants; C's self-host-by-10 for cost is rejected.

**Auth spike (resolved).** Better Auth over R07's Supabase Auth, because the `jwt` plugin's JWKS keeps issuance in the API. Week 1 includes a one-day spike proving a Better Auth JWT with `{sub, tenant_id, role, beat_ids}` drives `auth.parameter()` and the per-beat parameter query; fallback is a tiny token-exchange endpoint minting PowerSync JWTs from the Better Auth session.

### 7.3 Write path and conflict rules

The client writes domain rows locally; `/sync/upload` (protocol v1) maps each CRUD transaction's table set to a **command** (`PlaceOrder`, `RecordVisit`, `RecordReceipt`, `CompleteDelivery`, `ConfirmPack`, `RequestBargain`, `EditRetailerProfile`, `RecordTripCounts`) and dispatches it inside one DB transaction with tenant/actor settings from the JWT.

| Entity                    | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sales order (create)      | Insert-only from devices with `quoted_unit_price`, `applied_rules`, `price_version`, `priced_at`. Server **recomputes at the same version**; unequal at the same version = tampering or engine bug → `sync_errors` + alert. If `pricing_date_mode = 'order'`, the quoted version is honoured even after a month-end scheme change (B's approval-on-every-mismatch rejected: it floods approvals). If `'delivery'`, reprice at the current version and open an approval only above the owner-set tolerance (default ₹0, adjustable) — A's rule. Credit hold and per-SKU max server-enforced; `stop` rejects, `strict` opens an approval, `indicate` annotates. Retailer confirmation only after approval. |
| Sales order (edit/cancel) | While `draft                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | submitted | confirmed`; a manager's `picking` wins over a rep edit; rep sees "already picking" |
| Line qty                  | Field LWW while `draft`; afterwards only `pack_confirmations` change quantities                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

Business rejections return 2xx with `sync_errors(tenant_id, user_id, device_id, op_id, table, row_id, code, message_hi, message_en)` synced back to the device's "Needs attention" tray; 4xx is never returned to the uploader (it wedges the queue, R07 §3.2 rule 5). Server-owned fields flow back through the download stream.

### 7.4 Idempotency (resolved; Judge 3)

`sync_ops(tenant_id, device_id, op_id, outcome)` unique, retained ≥ 180 days; replay returns the stored outcome. `stock_ledger` and `journal_lines` carry `UNIQUE(tenant_id, idempotency_key)` so a replay after days offline cannot double-post even if `sync_ops` were pruned. Online oRPC mutations use `idempotencyKey` with Stripe semantics and 24-hour retention — the only place 24 hours applies. PowerSync does not advance a checkpoint while local mutations are unacknowledged (R07 §3.2 rule 6). CI replays a recorded upload log twice and asserts identical ledger state.

### 7.5 GPS points (the shared gap, resolved)

`trip_points` do **not** travel through the PowerSync queue: a device offline for hours would replay hundreds of GPS rows ahead of a cash receipt. The location task buffers points in a device-local table outside PowerSync and posts batches (30 s / 50 m, or on reconnect) to `POST /gps/points` with `(trip_id, device_id, ts)` for dedupe; the server drops points outside the trip window, upserts `vehicle_positions` and inserts `trip_points`. `device_id` is in every key — two-person crews carry two phones (C's `(trip_id, device_ts)` key rejected). Raw points pruned after 90 days by `dpdp.gps_retention`. The owner phone syncs `vehicle_positions`; the console reads an SSE feed of the same rows; latency ~30 s. **No WebSocket** (all judges): one fewer transport with sticky sessions behind an ALB.

### 7.6 Attachments and sync UX

Photos go through the attachment queue to S3 via pre-signed PUT; metadata rows sync normally; thumbnails cached locally. No "sync now" button: a status dot (synced / pending n / offline) and "last synced"; sync on connectivity change and app foreground; `expo-background-task` flushes on its ≥ 15-minute schedule when the app is closed.
