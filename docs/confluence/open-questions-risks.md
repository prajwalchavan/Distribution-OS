# 1. How to read this page

- **Open question** — a business decision only the founder (with Tarsun or the CA) can make. Each one names what it blocks and when the answer is needed.
- **Risk** — something that could go wrong. Each carries likelihood / impact, the mitigation already in the code, and what is still exposed today.
- **Not addressed** — something an earlier version of this space promised that is not built. Each is either _deliberately out of v1_ or _an open gap with an owner module_.

A gap with a **module owner** is scheduled work, not a surprise. A gap with **no owner** needs a decision before it becomes one.

# 6. Known technical debt carried

Recorded here because it is cheap to fix now and expensive after the first deployment.

1. **Two row-level-security policies need widening** at the next schema regeneration: a retailer may cancel a submitted order through the service but the policy allows updates only on drafts, and the order-transition table is staff-write-only so the service temporarily elevates the actor role. Both are noted in `docs/18` and both must be fixed before migrations leave this machine.
2. **Migrations are expand-only once deployed.** Two early migrations have never left the founder's machine and can still be regenerated. That freedom ends at the first deployment.
3. **The default user locale is still `hi-IN`** in the schema while the product decision (2026-09-04) is English only. Harmless today, confusing later.
4. **The verification gate keeps finding real defects** — four at each of the last two checkpoints, each fixed with a test so it cannot return. That is the gate working, and it is the reason module counts move slower than a feature list would suggest.
