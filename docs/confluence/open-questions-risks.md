# 1. How to read this page

- **Open question** — a business decision only the founder (with Tarsun or the CA) can make. Each one names what it blocks and when the answer is needed.
- **Risk** — something that could go wrong. Each carries likelihood / impact, the mitigation already in the code, and what is still exposed today.
- **Not addressed** — something an earlier version of this space promised that is not built. Each is either _deliberately out of v1_ or _an open gap with an owner module_.

A gap with a **module owner** is scheduled work, not a surprise. A gap with **no owner** needs a decision before it becomes one.

## Questions closed on 20–21 September

Four product questions the QA work surfaced were put to the founder and answered. They are recorded here so nobody re-opens them:

- **A scheme threshold counts the whole bill.** "Bills over ₹X" means the bill the shop is actually buying, including lines already under an exclusive scheme — such a line still earns nothing from the threshold scheme, but it now counts toward reaching it.
- **No permanent public link to a shop's papers.** Invoices, receipts and statements keep going out as files shared from the phone. A forever-URL carrying a shop's prices and balance is refused; if a link is ever wanted, it must expire.
- **One list order across all seven apps.** Every list reads newest first on the same column its own from/to window filters — server time for a queue of work, the document's own stamped date for a dated register, the record id only ever breaking a tie. The founder delegated this to the architect and this is the ruling: one rule, not a rule plus an exception.
- **A van may leave before its planned date, and the early departure is recorded.** The trip carries both the planned date and "departed early" beside it. Refusing an early departure would only push people to edit the plan, which destroys the record of what actually happened.

**Closed earlier and not re-opened:** who collects money, van-sale numbering, cash-discount timing, branding and white-label, UI language, screen layout, accountant scope, where the manager approves load-out, branches, AI scope, platform console, positioning, typeface, and the full set of QA batch-1 and batch-2 rulings. Each is a dated row in the Founder Decisions Register page and in `docs/22` §8.

# 6. Known technical debt carried

Recorded here because it is cheap to fix now and expensive after the first deployment — which is **this week**.

1. **The two row-level-security policies are widened.** The retailer-update policy now allows a shop to cancel its own submitted order, and the order-transition table carries a retailer-write policy, so the audit row is written by the shop rather than by an elevated actor. A deliberate, re-entrant `asSystem` escalation remains in the code for the narrow cases where a shop's own action must perform a staff-only write (reserving stock on its own submit); it is documented at its definition, restores the caller's role inside the same transaction, and always records the shopkeeper as the actor. That pattern, not the policies, is the residual.
2. **Migrations are expand-only once deployed, and deployment is days away.** Two early migrations have never left the founder's machine and can still be regenerated. **That freedom ends at go-live** — anything to be rewritten in the schema must be rewritten before the first deploy, not after.
3. **The default user locale is still `hi-IN`** in the schema while the product decision (2026-09-04) is English only. Harmless today, confusing later.
4. **The smoke-test blockers are cleared.** Three harness and seed faults (S-149, S-156, S-157) meant `pnpm smoke` could not reach a clean run on a fresh database, so lanes were being held to a bar they could not clear. All three are fixed, and a clean run of **1,618 calls, 0 BROKEN, on a freshly seeded database** is now recorded with its commit. The founder's own rule stands over it: the smoke gate is worked **failure by failure**, never as an all-or-nothing bar.
5. **The P0 on shared devices is closed.** Sign-out leaving the previous person's shops, orders and dues visible to the next was the most serious finding of the QA programme. It is now a never-list item and it is met on all three targets, measured from the wire rather than from the app's account of itself: a person's unsent work stays on that device for that person, uploads **first** at their next sign-in, and never reaches anyone else. A closed P0 is not a finished area, and the follow-on defects it exposed are tracked.
6. **The verification gate keeps finding real defects, and that is the point.** Two QA batches produced 34 and 158 findings; 153 of the second batch are merged. Several were faults no unit test would have caught — money banked twice, a shop told it owed ₹0 when it owed lakhs, a work list pointing at hundreds of things nobody could act on. It is the reason progress reads slower than a feature list would suggest, and the reason the numbers on this space can be trusted.
