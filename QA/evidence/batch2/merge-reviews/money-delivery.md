## Blockers

An owner adding proof to delivery X under an id proof of delivery Y holds is told "proof recorded" with Y's row (never-list #12 in spirit: the app says the proof is on X); an owner sending a consent id the driver's row holds gets the driver's consent as `item` — against the method's own rule "Always the CALLER's own row" (:238).
   - **Fix:** `and(eq(podEvidence.id, evidence.id), eq(podEvidence.deliveryId, delivery.id))` at :255 and `eq(podEvidence.deliveryId, deliveryId)` at :498; `and(eq(locationConsents.id, input.id), eq(locationConsents.userId, ctx.actorId))` at :247 and :281. A visible foreign row then falls through to the existing 409s; a real replay (same delivery / same person) still matches. Extend the two lane cases: in DOS-176 the `owner` presses `podId` on `theirs` → 409 `pod_id_taken`, `delivery_id` still `deliveryA1`; in DOS-177 the `owner` presses an id the driver's own consent holds → 409 `consent_id_taken`, the driver's row untouched. Update the 409 comments (":the row that holds this id is one RLS hides" becomes "one this caller cannot see, or another delivery's / person's").
