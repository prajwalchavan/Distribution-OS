The design is the one signed: the first presented kit overlay owns the one `<Modal>`; anything opened while it is up renders as a plain `<View absoluteFill accessibilityViewIsModal>` inside that Modal via `OverlayOutlet` (never a nested Modal); closes and unmounts resolve before opens in one microtask `flush()` (overlay-stack.ts:222-229); a root closed under a layer is retained with its panel dropped (:145-147, `useHostPanel`); a root unmounted under layers promotes the oldest layer (:118-134); `onRequestClose` (Android back) calls the top layer's onClose (:265-269). I traced the manager Approve-in-Sheet flow: orders/index.tsx:547 `setDeciding` → Dialog effect records `open` → flush makes it a layer of the Sheet → the layered Dialog returns `<></>` and hands `<DialogPanel>` to the Sheet's outlet, so no `presentViewController` is ever called for it; `commitDecision` (:349-358) closes only the Dialog, so the common path never retains. Money Bank it / Mark bounced (money/index.tsx:331/:344, confirms :532-538/:573-582) are the same shape; the bounce dialog's `<RupeeInput>` pad (:561) is a raw `<Modal>` inside the layer View, so it chains from the Sheet's own modal controller — the documented exception. The two deviations are sound on both platforms: (1) keeping the panel through dismissal is required by Modal.js `_shouldShowModal` (:278-281, iOS keeps children until onDismiss; Android returns null at once, so no empty animation there); (2) the flush flags, cancel-remove-on-request (StrictMode/Fast Refresh) and the `useLayerContent` unmount cleanup only tighten timing. Absolute-fill layers fill RN Modal's own container (Modal.js:379-385 `top:0, [side]:0, flex:1`). `useSyncExternalStore` snapshots are primitives, `OverlayOutlet` is `memo` and re-renders only from `version(hostId)`, so a keystroke in a layered controlled field reaches the input once, in one extra sync commit before paint. Re-render cost with one overlay: one microtask and one commit per open; a root re-render calls `setLayer(id, null)` which is a no-op (amendment c). The exhaustive walk (two Sheets, two Dialogs, open/close/unmount, ≤ 2 unflushed intents = every same-commit pair the 22 screens can produce, plus the verifier's widened runs to 3 intents, remounts and 2 M states) asserts both invariants after every flush; the orders real screens produce (layer open/close, both-close, owner swap both ways, screen unmount with root+layer) are all inside it.
