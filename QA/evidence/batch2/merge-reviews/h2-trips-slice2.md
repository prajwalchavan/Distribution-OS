## Minors (may follow)
1. trips.service.ts:1103-1107 — advisory locks are sorted per stop, not across a `create`'s stops. `create(stops: [B], [A])` racing `stops.add([A, B])` (sorted A, B) on another trip can deadlock; Postgres aborts one side with 40P01 after `deadlock_timeout`, which core does not catch, so one planner sees a 500 once and a 409 on retry. Two creates cannot deadlock (both hold the numbering-series row from `nextDocumentNumber` first), `addStop` vs `addStop` cannot (one stop each, sorted). Harmless at pilot volume; follow-up: in `create`, before the stops loop, take the same locks over the union of all stops' bills sorted (xact advisory locks stack, so `insertStop`'s own loop stays for `addStop`).
2. warehouse-app load/index.tsx:100-104 — while `board` is loading or failed, `unplanned` is empty and `packOnTrip` is shop-level: for a second or two an unplanned second bill of an on-trip shop is selectable. `picked` re-filters at render, so a Build in that window is the only exposure. Same lib limit: the board says "unplanned", not "on which trip", so a shop with two bills on two open trips today can have its other trip's bill loaded here (`trips.get` hides `stops[].deliveries` from warehouse). Both accepted by amendment (c)'s "where the board can tell".
3. load/index.tsx:249 prints the raw `row.state` enum in the trip row's secondary; W10:513 and the DOS-043 file did the same in a chip. Cosmetic.
4. trips.service.ts:1124 — `plannedOnOpenTrips(tx, [invoiceId])` once per bill of a stop; batching the stop's ids is one round trip. Bounded, so cosmetic.
5. migrations/0045_pack_confirmations_created_idx.sql — plain `CREATE INDEX`, as 0041/0042: drizzle's `migrate()` runs inside a transaction, so `CONCURRENTLY` is impossible from the migrator. On a lakhs-row `pack_confirmations` the build takes a SHARE lock (writes wait for its duration). Acceptable for the local-first goal and docs/20 names CONCURRENTLY only for the partition PK rebuild; docs/26's deploy row should say large-table indexes are built by hand CONCURRENTLY before `pnpm db:migrate`. Repo-wide, not this slice.
6. The board's bills page inherits `fulfilmentQueue`'s `desc(sales_orders.id)` order (fulfilment.ts:193): seeded hash ids sort above live UUIDv7 orders, so with more than 200 packed orders today's would land beyond "More bills". At pilot volume (≤ 10 packed) every bill is on page 1. Already recorded by the DOS-133 verdict as an unfiled P1; file it, not fix it here.
7. QA/tools/e2e/dos-131-plan-trip.mjs was not written (lane forbids QA/). The lost-reply replay, the disabled-row sentences and the accountant's M7 view are proven only by the pure lib tests and code reading; the main session's walk below covers them once.
