Nothing else changed (diff stat: 2 files, +117). I checked the lens by reading the code:

- **A stale answer after close is dropped.** Both poll callbacks compare the token (`:226` success, `:250` failure) before touching state. So after close, the old poll cannot show 'Challan ready', show an error, set `challanUrl` or call `documents.open`. `onClose` still clears the note and the URL.
- **A new poll after reopening works.** `openChallan` takes `++challanToken.current` (:220), which is always newer than the close bump. Reopening the same sheet starts a fresh poll, and attempt 0 opens a rendered challan. The unmount bump (:213-218) is unchanged.
- **Every way out goes through `onClose`.** On web: backdrop click, Escape and the Close button (web/feedback.tsx:158-177, 250-255). On web the desk side panel sits on a full-screen fixed backdrop (web/css.ts:109), so a second register row cannot be chosen while a sheet is open.
- **Web user-gesture rule (144bcfe) untouched.** The Print `onPress` still opens `challanUrl` synchronously before any await (:469-473). Only attempt 0 opens from the poll (:234-240).
- **Document-URL guard (9532a67) untouched.** `readyUrl = absoluteUrl(result.url)` and `printUrl = absoluteUrl(challanUrl)` are unchanged. The new test file has no `documents.open/print/share(` or `source={` text, so the kit guard (document-urls.test.ts:48-66) does not scan it as a call site.
- **Test.** It reads the source, following the manager app's `fulfilment-queue.test.ts` pattern. It is red on main at the last expect, because main's `onClose` has no bump, and green on the lane. Prettier --check through stdin (nothing written) is clean on both files.

## Minors

1. **The guard checks the shape of the source, not the behaviour** (verifier's note, confirmed). It passes a bump hidden inside an uncalled closure in `onClose`, and it fails `challanToken.current = challanToken.current + 1`. Keep the bump as a direct statement in `onClose`. Any future refactor of the panel must keep `testID="loadsheet-panel"` on the `<Sheet>`, or the guard fails with a "not found" message.
2. **One extra request after close.** A retry timer already scheduled at close still fires one more `warehouse.challans.pdf` (load-out.tsx:244-246). The token check drops the answer and no further retry is scheduled. It is harmless and outside the design ("nothing else"). A later P3 could add `if (challanToken.current !== token) return` inside the timer.
3. **Filing and naming.** The S-108 row says P3, the verifier rated it MAJOR (wrong document), and the build brief says P2. The main session picks the priority when it files DOS-174. The file and test title carry S-108, not DOS-174. Do not rename them just for the id: the commit already names the test.
4. **Gates not run on the merged tree.** The integrator runs frontend `pnpm lint && pnpm typecheck && pnpm test && pnpm format:check` on main after the merge. That covers manager-app and `@dos/ui` document-urls.test.ts.

## Defects outside the lane (by code reading, NOT TESTED)

1. **The kept challan link can expire before Print is pressed.** frontend/manager-app/app/fulfilment/load-out.tsx:238 keeps the poll's signed challan URL in `challanUrl`, and :469-473 opens it on Print with no age check. The link lives 15 minutes (backend/libs/core/src/platform/documents.ts:64), so a panel left open past that opens an expired `/storage` link that is refused (object-storage.ts:307). Fix: keep `expiresAt` with the URL and start a fresh poll once it has passed. P3.
2. **Escape closes the whole stack on web.** frontend/libs/ui/src/web/feedback.tsx:158-169 (called by Sheet :177 and Dialog :280): every open Sheet and Dialog adds its own document keydown listener with no top-most check. One Escape in M7's approve or cancel Dialog therefore also closes the load-sheet panel underneath (and cancels its challan poll). P3, kit (lean-kit-polish 21).
