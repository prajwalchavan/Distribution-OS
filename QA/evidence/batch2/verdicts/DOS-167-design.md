# DOS-167 — architect design (Fable, 2026-09-13)

Run `wf_3a18d87a-bab`. This design is the signed-off plan (P0, approved by the founder on 2026-09-13). The unsent-changes behaviour waits on the founder's answer to the question below.

## Summary for the founder

The phone's offline copy is one file per app, so the next person who signs in on that phone inherits the last person's shops, orders, dues and sync position; after a restart that includes another distributor's book for a moment.
Fix: one store per person-and-distributor, checked before anything is read, and wiped when they sign out; the online query cache and the sales draft get the same rule. Nothing from a previous user is ever drawn, on web, Android or iOS.
One question for you: when a rep signs out with changes not yet sent, keep them on the phone for that rep only (recommended) or refuse the sign-out until they are sent.

## Root cause

Confirmed by reading the code on main (/Users/prajwalchavan/Desktop/Distribution OS), consistent with QA/evidence/batch2/s-098/SUMMARY.md V5A and V5C:

1. ONE FILE PER APP, NO IDENTITY IN IT. `frontend/libs/offline/src/engine.ts:156` opens `this.options.databaseName ?? 'dos-offline.db'`; the three field apps pass a fixed name — `frontend/sales-app/app/_layout.tsx:299` "dos-sales.db", `frontend/delivery-app/app/_layout.tsx:299` "dos-delivery.db", `frontend/warehouse-app/app/_layout.tsx:305` "dos-warehouse.db". `react.tsx:112` keys the engine on `[enabled, deviceId, storeFactory, databaseName, pullIntervalMs, tenantId]` — the user is not in it, so rahul → amit (same tenant) is the SAME engine identity on the SAME file.

2. ROWS ARE PUBLISHED BEFORE ANY IDENTITY CHECK. `engine.ts:163-181` `start()` reads `schemaVersion`/`lastPulledAt`, `restoreManifest(store)` loads the previous run's shapes, then `this.bus.emit([...shapes, OUTBOX_CHANNEL])` — every mounted `useTable` (`react.tsx:194-223`) re-queries and paints whatever the file holds. The only guard is the network handshake that follows (`sync('start')`), which is the 0.4 s window of V5C where a Sai rep saw 30 Tarsun shops with dues.

3. THE STALE CHECK HAS NO USER. `engine.ts:341-345`: stale = `manifest.changed || schemaVersion differs || role differs || (tenantId known on both sides and differs)`. Same tenant, same role, same hash → not stale → the cursor is kept (`engine.ts:348-356`) and the data tables are kept. That is V5A: amit's first manifest sent rahul's `knownSchemaVersion`, his first pull sent rahul's `since`, 0 rows came back, and his beat never arrived. Also `engine.ts:347` writes `tenantId` into `_sync_state` only at the first manifest, so a store that never finished a handshake carries no tenant at all.

4. NOTHING WIPES AT SIGN-OUT. `engine.ts:200` `wipe()` has no caller anywhere in frontend/. The provider cleanup `react.tsx:101-105` calls `stop()` only (correct: it also runs on a token refresh, and the queue must survive that). `frontend/libs/api-client/src/react/index.tsx:117-121` `useSession().signOut` clears the QueryCache only.

Two more stores of the same class, found while reading, in scope because goal 1 is "nothing from a previous user is ever rendered":
5. `frontend/libs/api-client/src/react/index.tsx:54-68` — the QueryCache is cleared only by the `useSession()` wrappers (:117-129). A forced sign-out (`client.ts:153-172` refreshNow → `session.clear()` on a 401) never clears it; the next user's `useQuery` on the same key repaints the previous user's server rows first (UX-00 §6.13 stale-while-revalidate) until revalidation. All seven apps.
6. `frontend/sales-app/src/lib/draft.ts:36,92,111` — the per-shop order draft is stored in platform storage under `dos.sales.draft.<retailerId>` with no user, so a same-tenant colleague who opens that shop restores the previous rep's typed lines (V1 saw the key survive sign-out).

## Design

Everything below is in build order. Quote paths from /Users/prajwalchavan/Desktop/Distribution OS. Test-first: every step names its DOS-167 test (see `tests`); write it, see it red, then make it green. No backend change of any kind: the sync contract, sync.service.ts, PERMISSIONS and migrations are untouched, so `pnpm smoke` and the READMEs are unaffected.

THE SHAPE OF THE FIX (three layers, any one of which alone closes the leak):
- Layer A, keying: the device store is one SQLite file per (app, user, distributor). Two identities can never open the same file, so a fresh identity has no rows and no cursor by construction — its first pull is a full snapshot.
- Layer B, the stamp: the file records who it belongs to in `_sync_state` (`userId`, `tenantId`, `role`) the moment it is opened, and `start()` compares that stamp with the signed-in identity BEFORE it restores shapes or publishes any table. A mismatch (a wrong-name bug, a test's fixed store) wipes everything, outbox included, and logs it. The manifest handshake stays as the third check (role, schema hash), no longer the only one.
- Layer C, leaving: sign-out ends the engine — data tables, cursor, manifest, errors mirror and GPS buffer go, the file is deleted — before the auth session is cleared. Unsent changes follow the founder's answer (default below: kept in that person's own file, never anyone else's). A distributor switch swaps to the other file and wipes nothing (same person, still signed in). The api-client's QueryCache and the sales draft are keyed by identity the same way.

The PlatformSession (admin console) has no tenant: `bindCacheToSession` takes the widened snapshot and keys on `user.id` alone when there is no `tenant` — handle with a small `keyOf(snapshot)` that reads `tenant?.id ?? STEP 3 — the engine (frontend/libs/offline/src/engine.ts).
3a. `SyncEngineOptions`: `identity?: SyncIdentity` REPLACES `tenantId?: string` (three app callers and engine.test.ts:146-176 change; the harness passes none). Doc: "Who this database belongs to. Absent only in the harness and in tests that model a device with no sign-in."
3b. Export `storeNameFor(prefix: string, identity: SyncIdentity): string` → `${prefix}__u-${userId}__t-${tenantId}.db`, after asserting `prefix` matches `/^[A-Za-z0-9-]+$/` and both ids match `/^[A-Za-z0-9-]{1,64}$/` (UUIDs); throw otherwise — a file name never carries an unchecked string. Also export `legacyStoreName(prefix)` → `${prefix}.db`. Lossless on purpose: no hash, so two identities cannot collide. (The name is ignored by the memory adapter, which is why Layer B exists.)
3c. `start()`, new order: open → `createSystemTables` → the sending→queued revert → **`await this.claimIdentity(store)`** → `writeState deviceId` → read schemaVersion/lastPulledAt → `restoreManifest` → counts → ready → emit → `sync('start')` → poll. `claimIdentity`: read `userId`, `tenantId`, `role`; if `options.identity` is set and ANY of the three is stored and (`userId` or `tenantId`) differs → `await this.wipeAll(store)` (below) and `onLog('offline: store belonged to another identity; wiped', { stored, wanted })`; then write the three keys from `options.identity`. If `options.identity` is absent, skip entirely (legacy/harness behaviour, unchanged). Because this runs before `restoreManifest` and before the first `bus.emit`, no shape of a foreign identity is ever loaded and no screen can query its rows; because it runs before `sync('start')`, a foreign outbox is never uploaded under this token.
3d. `wipeAll(store)` (private): drop every data table named in the STORED manifest JSON (read `manifest` state and parse; fall back to the current `shapes` keys), `DELETE FROM _outbox`, `_sync_errors`, `_gps_buffer`, and null every state key except `deviceId`. Reset `shapes`, `manifestTables`, `schemaVersion`, `lastPulledAt`.
3e. `applyManifest`: `this.options.tenantId` → `this.options.identity?.tenantId`; the rest of the comparison stays (schema hash, role, tenant). Keep line :347 (harmless now that the stamp is written at start).
3f. `wipe(options: { keepQueue?: boolean } = {})` — the sign-out wipe, made real: drop the data tables, `_gps_buffer`, and the state keys `cursor, schemaVersion, role, lastPulledAt, manifest, protocol`; `_outbox` and `_sync_errors` are deleted unless `keepQueue`; `userId`/`tenantId`/`deviceId` stay (the file is still that person's). Then reset in-memory shapes/manifest/schemaVersion/lastPulledAt, `refreshCounts`, **emit every dropped table plus OUTBOX_CHANNEL and ERRORS_CHANNEL** (today's wipe emits no table change, so a mounted list would keep its rows in React state until unmount), `emitStatus`.
3g. `end(options: { keepQueue: boolean }): Promise<void>` — what sign-out calls. Order: `this.started = false` and clear both timers (so `pullLoop`/`flushInternal` leave at their next iteration, engine.ts:443/:638); `await this.flushChain.catch(() => {})` (no batch mid-claim); `await this.wipe(options)`; `await store.close()`; if `!keepQueue` → `await store.destroy?.()`; `this.store = null`; `this.ended = true`. A later `stop()` on an ended engine is a no-op (the provider's cleanup will call it). If any step throws, the error propagates after `this.store = null` is still set — the caller signs out regardless (amendment (g)). With `keepQueue`, the file survives with its outbox and errors mirror and no read set; the same identity's next `start()` finds `pending > 0`, and `applyManifest` (stale: no schemaVersion) flushes the queue BEFORE the re-snapshot exactly as today (:360), then pulls with no cursor — `claim()`/`settle()` skip `setPending` because no shape is loaded, which is already how they behave.
3h. `static async sweepIdentityStores(storeFactory, prefix, identities: SyncIdentity[], onLog?): Promise<{ destroyed: number; kept: { identity, pending }[] }>` — for a person with several distributors: for each identity, open `storeNameFor(prefix, identity)`, `createSystemTables`, count `_outbox` rows with status in ('queued','sending','rejected'); if 0 → `destroy?.()` (else `close()` and report the count). Best effort per file (a failure is logged and skipped). Called by the sign-out flow with the user's OTHER memberships.
3i. `status()` unchanged. `tables()` unchanged. Nothing else in the engine moves: `retry()`, `needsAttention()`, `pullErrors()` (lean-libs-offline-boot's DOS-046 region) are not touched.

## Binding amendments

- (a) The store name is lossless: `storeNameFor(prefix, identity)` embeds the raw userId and tenantId after a character-class check and never a hash; two identities map to one file only when both ids are equal. `storePrefix` is a literal per app ('dos-sales', 'dos-delivery', 'dos-warehouse'); no app computes a file name by hand.
- (b) `claimIdentity` runs in `start()` BEFORE `restoreManifest`, before the first `bus.emit` and before `sync('start')`. A stamped store whose userId or tenantId differs from `options.identity` is wiped whole (data tables from the stored manifest, `_outbox`, `_sync_errors`, `_gps_buffer`, every state key but `deviceId`) and the wipe is logged; a foreign outbox is never uploaded under the new token. A store with no stamp is simply stamped. An engine with no `identity` option (harness, legacy tests) skips the check unchanged.
- (c) `wipe()` and `end()` always drop the read set (data tables, cursor, schemaVersion, role, manifest, protocol, lastPulledAt, GPS) and emit every dropped table plus OUTBOX_CHANNEL and ERRORS_CHANNEL. `keepQueue: true` keeps `_outbox` and `_sync_errors` rows and the file; `keepQueue: false` deletes the file through `SyncStore.destroy()`. `userId`/`tenantId`/`deviceId` are never cleared by `wipe` — the file stays that person's.
- (d) `end()` sets `started = false`, clears the timers and awaits the flush chain before it drops anything, so no pull page or upload batch lands on a dropped table; a `stop()` after `end()` is a no-op. `end()` is called before `client.signOut()` (the access token is needed for 'Send now', and the revoke may take the 20 s deadline offline); the session is cleared even when `end()` throws.
- (e) A distributor switch wipes nothing: the provider stops the old engine (queue kept in that person's file) and starts a new one on `storeNameFor(prefix, newIdentity)`. The switch is asked about (the same sheet, 'Switch anyway') only when pending + rejected > 0. Switching back reopens the earlier file and continues from its own cursor.
- (f) Sign-out with pending + rejected = 0 stays one tap: no sheet, the current file is deleted, the person's other-membership files are swept (`sweepIdentityStores`: deleted when empty, kept and reported when they hold queued or rejected ops), sales drafts of that user are forgotten. Sign-out with anything queued or rejected shows the sheet: 'Send now' only while `status.online`; 'Sign out, keep them here' calls `end({ keepQueue: true })`. Discard is never offered here — it stays in the Needs-attention tray with its audit line (docs/27 §11). This is the recommended default pending the founder's answer; if the founder picks 'refuse until sent', the 'keep' button becomes a refusal sentence and `keepQueue` stays in the engine for the forced-sign-out path.
- (g) Nothing is rendered from any store before the identity is settled: the QueryCache is cleared on every `identityKey` change by `bindCacheToSession` inside `ApiProvider` (all seven apps, forced sign-out included), and the sales draft key carries the userId. No screen gains a second permission or identity list; screens keep importing only `@dos/ui` and `@dos/offline/react`.
- (h) `SyncIdentity` is `@dos/offline`'s own type; the package never imports `@dos/api-client` at runtime. `sessionIdentity()` / `identityKey()` live in `@dos/api-client` (session.ts) and are the only definition of 'who is signed in' the apps pass across.
- (i) The legacy fixed-name file (`<prefix>.db`) is destroyed once per mount, best effort; every QA device and browser profile that ran a pre-DOS-167 build is otherwise left holding the last rep's rows at rest.
- (j) No backend change: contract, sync.service.ts, PERMISSIONS, migrations untouched; `pnpm smoke` and generated READMEs unaffected. No kit (`@dos/ui`) change: the leave sheet is app-level on `Sheet`/`Stack`/`Button`/`Txt`; `Dialog` is not used because it carries exactly one confirm verb.
- (k) engine.test.ts is touched only at the DISTRIBUTOR-change test (:146-176, `tenantId` → `identity`, and its comment now says the wipe happens at open); every new engine test goes in the new `frontend/libs/offline/src/identity.test.ts` so lean-libs-offline-boot's DOS-046 additions to engine.test.ts merge without a conflict.
- (l) Files outside the list below are not edited. docs/22 rows are handed to the main session in the lane result; QA/ is not lane-owned (the verifier extends the S-98 script under QA/tools/e2e when it runs the proof).

## Founder question

**When a rep signs out on a phone that still holds changes not yet sent to the office (an order queued in a dead spot, a delivery not yet uploaded), what should happen?**

Recommended default: Keep them on that phone for that person only. The sign-out screen says '3 changes have not reached the office. They stay on this phone for Rahul only and go the next time Rahul signs in here. Nobody else can see them.' with 'Send now' offered whenever there is signal. The next person who signs in never sees them; when Rahul signs in again on that phone they go out first, before his data refreshes. The phone can always be handed over, and no order is ever lost.

- Alternative: Refuse the sign-out until the changes are sent or thrown away from the Needs-attention tray (what docs/27 §12 says today). Safer-looking, but in a dead spot the rep cannot sign out at all, so the phone is handed over still signed in as him — the very leak this fixes — or he throws a shop's order away to leave.
- Alternative: Throw unsent changes away at sign-out. Not recommended: a shop's order vanishes silently.
