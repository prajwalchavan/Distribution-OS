# DOS-146 — architect verdict (Fable, 2026-09-13)
**Verdict:** APPROVE WITH AMENDMENTS

Root cause confirmed by re-trace: `frontend/delivery-app/app/trip/start.tsx:75` lets `null` mean both "untouched" and "emptied"; line 290 (`cashPaise ?? detail?.openingCashPaise ?? null`) and line 347 turn every emptied entry back into the plan, and the kit's DOS-060 rule (`reconcilePadEntry`, `frontend/libs/ui/src/money.ts:162-164`) then shows the parent's ₹3,000 so the next digit appends. No second code cause: `trips.service.ts:388` applies `input.openingCashPaise ?? trip.openingCashPaise` (a 0 is written), `DepartTripInput.openingCashPaise` is `PaiseSchema.nonnegative().optional()` (`contracts/src/delivery.ts:735`), `cache.invalidate` (`api-client/src/cache.ts:200-210`) keeps `data` so `isLoading` stays false and the form never remounts on the `['trip']` invalidation, `<Money>` treats 0 as a value (`native/money.tsx:79`). Design is minimal: screen only, no contract, permission, schema, kit, sync or string change; the pure module + source-reading guard follows DOS-061/DOS-077 precedent and is the only way to get a red test for a screen that cannot be imported under vitest.

## Decisions
- technical: an emptied field is 0 in screen state and IS sent (`openingCashPaise: 0`); `null` stays "untouched" and is left out of depart. No `useEffect` seeding (adds a seeding flag and a refetch race), no "Use planned float" chip, no kit change. `openingCashShown` equals today's line 290 on purpose; the behavioural change is `openingCashEntered` alone — do not inline it or "improve" it to `?? 0`.
- technical: the DOS-060 append-on-reopen rule stays (the finding's step 4 still reads ₹3,00,04,756 when digits are typed onto the untouched ₹3,000). The confirm body prints the float before anything is written; changing the kit's first-key behaviour is a separate kit slice (see new findings).
- technical: `retailer-app/app/pay.tsx:141` and `manager-app/app/inbound/documents.tsx:418` are the same class and are excluded here (charter: no adjacent fixes; `?? 0` is the wrong rule on Pay).
- FOUNDER DEFAULT: at trip start, an emptied "Cash handed to you" means a ₹0 float and is written as the trip's float at depart (the dialog says "float ₹0.00"); an untouched field keeps the float planned at the office. Record in docs/22 §8 (2026-09-13, QA DOS-146).
