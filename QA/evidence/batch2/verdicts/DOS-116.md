## Decisions
- technical: no `return_expired`. `credit_note_reason` has one unsaleable reason and the doorstep already books an `expired` line as `return_damaged` (deliveries.service.ts:187-188), so the founder's "damaged or expired" row (docs/22:277) is satisfied by the one reason. Adding a reason is an enum migration + PDF label + claims split: a separate item.
- technical: the rule is enforced in the service, not as a Zod refinement, so the 400 carries DOS-058's `data.code` shape and the in-process `raiseForDelivery` path is covered by the same lines.
- technical: no inverse rule. `return_saleable`, `short_delivery` and `cancellation` lines may still be `saleable:false`; the doorstep's mixed return depends on it (deliveries.service.ts:187-205).
- technical: no re-check at `issue()`. `draft()` is the only writer, nothing is deployed, dos_qa has 0 drafts; verify step 0 re-checks before the running-product pass.
- technical: contract default → optional is a wire-compatible change: `z.input` is `saleable?: boolean | undefined` before and after, so no frontend type change; only `/docs/openapi.json` loses `default: true`; README examples render `true` either way (sample.ts:171-174, :185-188, :203-204).
- FOUNDER DEFAULT: expired goods returned at the desk are booked as `return_damaged` and the note prints "Goods returned (damaged)" (documents/templates/credit-note.ts:18); a distinct expired reason is deferred.
