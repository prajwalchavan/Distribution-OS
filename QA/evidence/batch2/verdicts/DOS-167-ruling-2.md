## The facts the ruling rests on

- wa-sqlite's VFS declares `mxPathname = 64` (expo-sqlite/web/wa-sqlite/VFS.js:10) and SQLite refuses to open when `strlen(path) + 8 > mxPathname` (the journal suffix is reserved), so the databasePath expo-sqlite web passes — `'./' + name` (SQLiteModule.ts:403 `defaultDatabaseDirectory = '.'`, pathUtils `createDatabasePath`) — must be ≤ 56 characters: names of ≤ 54 open, 55+ fail with `sqlite3_open_v2`. diag-04 measured exactly that (56 opens, 57 fails); the 199952b names are 92–96. The AccessHandlePoolVFS header itself holds 512 bytes, so the pool is not the limit.
- `openStore` on both platforms swallows the failure and returns `createMemoryStore()` with no log; the engine's `status().persistent` is then false, which only the sales beat line (`s0.notPersisted`) and the delivery/warehouse settings lines show. The kit's `ConnectionState` (libs/ui/src/types.ts:353) has no persistence field, so the strip cannot say it without a kit change.
- Android proof: every step passed on the long names (native has a 255-byte limit), including keep-sign-out, the kept file's contents, the resend before the re-snapshot, and the `dos-sales.db` upgrade. The count read "2 changes" for one order with one line on both platforms (S-121).
- The tray discards refused ops only (`orders/attention.tsx:99`); a queued op has no discard anywhere, by design (f).

## (s) THE NAME — mandatory

Format: `<app><user><distributor>`, exactly 51 characters, lowercase `[0-9a-z]` only, no separators, no extension.
- `<app>` is one letter from a table in engine.ts: `dos-sales → s`, `dos-delivery → d`, `dos-warehouse → w`, `dos-harness → h`; any other prefix throws. `storePrefix` props and `legacyStoreName(prefix) = <prefix>.db` are unchanged.
- `<user>` and `<distributor>` are each the id's 128-bit value written in base 36, zero-padded to 25 digits (36^25 > 2^128 > 36^24). Build: the id must match `/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i` (a canonical UUID; anything else throws — a file name never carries an unchecked string, and every id in this system is a UUID), lowercase it, drop the hyphens, `BigInt('0x' + hex).toString(36).padStart(25, '0')`. Parse: `parseStoreName(name)` matches `/^([sdwh])([0-9a-z]{25})([0-9a-z]{25})$/`, turns each 25-digit group back through base 36 into 32 hex digits and re-hyphenates 8-4-4-4-12; exported from engine.ts and shared.ts, and docs/27 §2 carries the one-line `node -e` decode for a QA listing. Hermes has BigInt (RN ≥ 0.70); if the Android proof's first run finds `typeof BigInt === 'undefined'`, the builder does the base-36 division on four 32-bit limbs — the format is the rule, not the arithmetic.
- Fit: databasePath `'./' + 51 = 53 ≤ 56` on web (margin 3 characters, and the only thing that can eat it is expo-sqlite's own `defaultDatabaseDirectory`, pinned at 57.0.2 in the catalog); 51 of 255 bytes on Android and iOS. Rahul at Tarsun (dos_qa ids 8760e17e-…-1e02fffa1ad7 / 01a09a5b-…-b93c569b0099): `s80j3azqcg6our25a35rhwbg7r03guzv9zghwmmy1imsvb8cmft`.
- Lossless and collision-free, proven: canonical UUID ↔ 128-bit integer is a bijection; a 128-bit integer ↦ 25-digit zero-padded base-36 string is injective; the alphabet has one case, so no case-folding filesystem (the iOS simulator's container sits on a case-insensitive macOS volume) can identify two distinct names; fixed widths make the concatenation unambiguous. Hence (app, userId, tenantId) ↦ name is injective on every store we run (OPFS pool header compare, ext4/f2fs, APFS). No hash anywhere. Amendment (a) stands with this format in place of `<prefix>__u-…__t-….db`.
- Files created under the 199952b names: on web none ever existed (the open failed before a header was written; the pool holds only empty files) — nothing to do. On the QA phones the long name is exported as `interimStoreName(prefix, identity)` and the provider's legacy effect (react.tsx:165) sweeps it ONCE for the signed-in identity with the sibling-sweep rule — deleted when it holds nothing queued, sending or refused; kept and logged (`offline: kept the store from before ruling 2`) when it does — through a generalised `SyncEngine.sweepStores(storeFactory, names, onLog)` that `sweepIdentityStores` now calls. The legacy `<prefix>.db` keeps its plain destroy (amendment i). No customer device has either name (pre-release).
- Docs: docs/27 §2 line 40 and §13 test 12, the package README line 45, and the docs/22 §8 row (main session) state the new format and its limit.

## (u) THE ENQUEUE GAP — mandatory

- Engine: `enqueueMany(inputs: readonly EnqueueInput[]): Promise<string[]>` — one `requireStore()` gate, every input's shape and `writable` checked BEFORE anything is written (one bad line refuses the whole order), one `inHand`, ONE `store.transaction` inserting the outbox rows in call order (ascending `seq`, header first, so FIFO still delivers the header before its lines) and applying each locally, then one `refreshCounts`, one emit of every table touched plus `OUTBOX_CHANNEL`, one `flush()`. `enqueue(input)` becomes `(await enqueueMany([input]))[0]`. `useOutbox()` exposes `enqueueMany`.
- `useEnqueueOrder` (sales queue.ts) builds the header and its lines and calls `enqueueMany` once. Outcome: the phone and the office hold the whole order or none of it — refused at the gate, the rep sees the sentence of (v) and nothing is queued; past the gate, `end()` waits for it, counts it and keeps the file (m2, m3). A header-only draft can no longer come from a sign-out. Delivery and warehouse already queue one op per fact (`deliveries` carries its lines inline; `receipts`, `trip_stops`, `pick_lines` are single facts) — no change. Upload batching (≤ 50 ops, DOS-056 bytes) is untouched.
- `leaveNow` (three apps' leave.ts): `LeaveSteps.end` returns `Promise<{ kept: boolean } | void>`; `kept = result?.kept ?? keepQueue`. The sibling sweep runs on EVERY sign-out (it deletes only files with nothing unsent — merge review minor 2); `forgetDrafts` runs only when `!kept`, so a file kept by the re-count keeps that person's drafts with it.

## (w) THE COUNT — out of scope, S-121 stays (P3)

"2 changes" / "2 waiting to send" for a one-line order is true to the outbox and is NOT a DOS-167 guarantee.
