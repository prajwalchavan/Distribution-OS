# DOS-080 — architect verdict (Fable, 2026-09-13)
**Verdict:** APPROVE WITH AMENDMENTS

Root cause confirmed by reading and by dos_qa: `price_list_items` has 696 rows / 696 distinct instants (no ties), the touch trigger stamps `clock_timestamp()` on INSERT and UPDATE, and `sync.service.ts:278` hands each of a rep's 21 tables 23 rows while `:297-300`/`:311` hold the cursor at the earliest full table. The finding's keyset-cursor mechanism is wrong and the plan is right to drop it. The cross-table cut (page = the `limit` earliest instants across the read set, ties completed, cursor = last instant delivered) keeps the `{v:1,t}` cursor, needs no contract, permission, schema, README or client change, and honours the contract's own words at `contracts/src/sync.ts:229`. Root cause 7 (`:311` compares a µs watermark with a ms `asOf` cursor as strings: `.123456Z` < `.123Z`) is real and is correctly removed rather than ported. Second-cause check: in-app navigation does not restart the engine (`react.tsx:112` deps, memoised device id in `sales-app/app/_layout.tsx:291`); the "per screen" half is the dev Metro memory store re-snapshotting on reload — see new findings.

## Decisions
- technical: cross-table cut over (i) a per-table keyset cursor (37 × 27 chars breaks the 256-char `since` cap; contract change) and (ii) a table-sequential v2 cursor (changes mid-pass semantics and the overlap rule). Cursor format, `PullIn`/`PullOut`, `PERMISSIONS`, migrations: none change.
- technical: `PullRequest.untilText` and `PullResult.at`/`deletedAt` are internal to `@dos/core` (`modules/sync/index.ts` re-exports types only; all 37 registrations go through `tablePull`). `at`/`deletedAt` are required fields so a hand-written handler cannot forget them; the `desk_only` stub gets `at: ['']`.
- technical: trim rule `instant <= cut`, empty instants always kept, the pinned path (`saturated && wm.at === ''`) delivers untrimmed with the cursor held — today's behaviour exactly.
- technical: lane = NEW lane **h10-syncpull** from main, built now (no migration, no dependency on h1). Merge order: h10 merges before h7-syncdoor branches (h7 waits on h1 anyway); if h7 has branched first, h7 rebases after h10 per amendment (e). Shares nothing with h1/h2/h3/h5/h8/h9; shares docs/27 with DOS-056 in different sections.
- technical: the web reload re-snapshot is not fixed here (memory store by design when the page is not cross-origin isolated); it becomes ≤ 25 calls and is recorded as a dev-tooling finding below.
- FOUNDER DEFAULT: none.

## Risks for the builder
- Read amplification is inherent: a later table may hold EARLIER rows than the ones already held, so every table must read `limit + 1` (plus ties) — never shrink a later table's limit by what is held. Worst case before trimming is 21 × 501 rows for a rep and 37 × 501 for the desk, in memory for one request; queries stay index range scans on `(tenant_id, updated_at)`. If profiling shows pressure, the follow-up is an instants-first two-phase read, not a smaller per-table limit.
- `until` must bound the rows query, the tie query and the FIRST tombstone query; the tombstone tie query is bounded by `= watermark` already.
- `readTombstones` keeps ids and instants paired AFTER the survivors filter (test 4 depends on `wm.at`, not on the kept ids).
- Never compare an instant against `sinceText` as a string; `sinceText` may be ms-precision from `asOf`.
- `input.tables` is not deduplicated (`:276`); a repeated name runs the handler twice and double-counts `held`. Dedupe with a `Set` while in the function.
- Keep the `since === null` push of empty tables (the two table-list tests read page 1).
- Spec fixtures: insert one row per statement (own `clock_timestamp()`), `markCursor()` from the database clock, tests appended after 'replays an upload batch twice…'. Watch the 30 s vitest timeout on the founder's polluted `dos` database (amendment c).
