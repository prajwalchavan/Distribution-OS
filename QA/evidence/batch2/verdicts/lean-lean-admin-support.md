## DOS-110 — design-ready

### Design

ANSWER TO THE QUEUE QUESTION: a new `lapsed` value in `SupportGrantStatusSchema`, derived by ONE `statusOf()` both services import, excluded from `openOnly` and `status=requested`, READMEs regenerated (the DOS-108 verdict's direction). Not `expired` + `decidedAt null`: `expired` means a window that WAS open and closed by the clock (the console prints it 'Closed', the owner history too); overloading it would make the chip lie for an ask that never opened and would force every client to keep a `decidedAt`-null sub-rule, the same client duplication this fix removes. Adding an output enum value is expand-only on the wire, `status=lapsed` as a filter comes free (docs/23 §10 row 12's third word), and h13's `supportDecision` already closes by default on a status it does not know (DOS-108 amendment (c)). No business rule changes: the founder's 2026-09-05 rule (time-boxed, owner-approved) already makes an unanswered ask un-approvable after its own hours and owner-service enforces it as 409 `request_expired`; DOS-110 only names that state on the read side.

ROOT CAUSE. `backend/libs/core/src/modules/tenancy/support.service.ts:276-280` `statusOf()` returns 'requested' for every unapproved, unrevoked row whatever the clock; `:241-246` `openOnly()` is `revoked_at IS NULL AND (approved_at IS NULL OR expires_at > now())`, which keeps every lapsed ask for ever; `:250-251` `statusPredicate('requested')` ignores the deadline. `backend/libs/core/src/modules/platform-admin/support-grants.ts:19-23` is a SECOND `statusOf` with the same hole and `platform-admin/support.service.ts:235-263` duplicates both predicates. The write side already knows the truth (`tenancy/support.service.ts:123-132`, 409 `request_expired`); only the reads lie, so two apps each grew an `askLapsed` clock (`frontend/admin-app/src/lib/ui.tsx:365-372`; h13's `frontend/owner-app/src/lib/support.ts`).

### Binding amendments

- (a) `lapsed` is appended LAST in `SupportGrantStatusSchema`: the README sampler and `pnpm smoke` take an enum's first value, so the published examples keep `requested`.
- (b) Exactly one `statusOf` and one pair of SQL predicates exist in the product, in `tenancy/support-status.ts`, exported through `tenancy/index.ts`; `platform-admin/support-grants.ts` keeps only `toSupportGrant`. A second `statusOf`, or a hand-written `expires_at > now()` in platform-admin, is a verifier fail.
- (c) The lapse clock is the row's `expires_at` while unapproved, in TS and SQL alike; the server never recomputes `requested_at + requested_hours`. `expiresAt` on the wire stays null until approval — no new field.
- (d) `revoke` on a lapsed ask answers 409 `request_expired` on BOTH services, so `rejected` keeps meaning 'the owner said no' and `revoked` 'shut while open'. `approve`'s existing 409 stays the guarantee and is not rewritten.
- (e) Every client clock goes: `askLapsed` is deleted from `admin-app/src/lib/ui.tsx` and `owner-app/src/lib/support.ts`; the admin views send the server's filters (`status: 'approved'`, `status: 'requested'`) and filter nothing client-side; `grep -rn askLapsed frontend/` returns nothing after the fix.
- (f) Owner `supportDecision`: `waiting` = server `requested` AND at least one offerable hour; everything else `closed` by default (DOS-108 (c) stands). No owner string is added; 'Lapsed' is the humanised chip.
- (g) `now` is read once per `list()` on the server and once per render in the apps, never per row.
- (h) Order of work: contract → build contracts → `support-status.ts` + both services → core specs red then green → `pnpm docs:readme` → admin app → owner app → docs/23 row 12. The two frontend halves start only after h10 (admin vitest harness, DOS-109/107) and h13 (DOS-108's `support.ts`) are merged to main; do not build from the h13 worktree, whose working copy currently shows `support.ts` and `refusal.tsx` deleted and uncommitted.
- (i) Out of scope, do not fold in: the DOS-108 verdict's new finding that `revoke` on an already-EXPIRED approved grant records `revoked` instead of refusing. The guard line added by (d) is where that later fix goes.
