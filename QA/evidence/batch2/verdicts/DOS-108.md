# DOS-108 — architect verdict (Fable, 2026-09-13)
**Verdict:** APPROVE WITH AMENDMENTS

Root cause holds on every citation: `<Segments>` slices to three in both renderers (web/controls.tsx:387, native/controls.tsx:421), so the fourth item at owner-app/app/settings/index.tsx:257 never renders; the fixed `hours: 4` (:84) collides with owner-service's shorten-only rule (tenancy/support.service.ts:117-132); the only decision buttons live in a Register column no phone rendering draws (web/list.tsx:513-540); `.then(done, done)` (:466-467) hides every refusal. The backend is right and covered (support.spec.ts:119-279); tenancy.support.* stay OWNER_ONLY (permissions.ts:392-394). No contract, permission or schema change. Design is minimal and correct: one read (`list({})`, default limit 50, newest first, no N+1), mutations idempotent through `useMutation`'s input-keyed intent, refuse = `revoke` on a requested row, no Sheet (DOS-164 safe), cards are plain Stacks/Buttons so desk, 390 px web, Android and iOS get the same controls. Always sending `hours` is right: an omitted `hours` approves the STORED `expires_at`, which the seed sets to 29 days on a "72 h" ask (see new findings).

## Decisions
- technical: Chips (single-select) replaces Segments for the four views; no kit change in this fix; `Segments` import stays for settings-pod.
- technical: Refuse and Revoke both call `tenancy.support.revoke`; no client-side status; `hours` is always sent, never omitted.
- technical: hour options = ascending union of {1,2,4,8,24,48,72} and `requestedHours`, each ≤ requestedHours and with `requestedAt + h` strictly after now; "Open until" = requestedAt + h (the server's measure), never now + h.
- technical (decision 1): no Settings badge in this fix — option (a). A badge after DOS-110 is one `list({ openOnly: true })` read; before DOS-110 it would count lapsed asks unless _layout.tsx carried a second `askLapsed` copy. Not a product call: the finding's Expected does not ask for it.
